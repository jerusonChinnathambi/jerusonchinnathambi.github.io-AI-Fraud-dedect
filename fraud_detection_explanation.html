AI Fraud Detection System Explanation

This document explains the input values used in the AI Fraud Detection System and how the trained XGBoost model predicts whether a financial transaction is fraudulent or legitimate.

1. Purpose of the System

The purpose of this project is to detect fraudulent financial transactions using machine learning. The system analyzes transaction amount and account balance changes before and after a transaction. Based on these patterns, the trained XGBoost model predicts whether the transaction is likely to be fraud.

2. Dataset Fields Used by the Model

The model uses five numeric input fields from the financial transaction dataset. These values represent the money transferred and the balance changes in the sender and receiver accounts.

Field Name Meaning Simple Explanation
amount Transaction Amount The amount of money being transferred.
oldbalanceOrg Old Balance Origin The sender's account balance before the transaction.
newbalanceOrig New Balance Origin The sender's account balance after the transaction.
oldbalanceDest Old Balance Destination The receiver's account balance before the transaction.
newbalanceDest New Balance Destination The receiver's account balance after the transaction.

3. What Does "Origin" Mean?

In the dataset, "origin" means the account where the money comes from. In simple words, it is the sender's account. For example, if a customer sends money to another person, the customer's account is the origin account.

4. What Does "Destination" Mean?

"Destination" means the account where the money goes. In simple words, it is the receiver's account. If a customer sends money to another person, the other person's account is the destination account.

5. Example of a Normal Transaction

In a normal transaction, the sender's balance decreases by the transaction amount and the receiver's balance increases by the transaction amount.

Input Value
Transaction Amount 2400
Old Balance Origin 52000
New Balance Origin 49600
Old Balance Destination 11000
New Balance Destination 13400

Explanation: The sender had 52,000 before the transaction. After sending 2,400, the sender's balance became 49,600. The receiver had 11,000 before the transaction and 13,400 after receiving the money.

6. Example of a Suspicious Transaction

A transaction can look suspicious when the sender's account is emptied or when the balance changes are unusual.

Input Value
Transaction Amount 181000
Old Balance Origin 181000
New Balance Origin 0
Old Balance Destination 0
New Balance Destination 181000

Explanation: The sender had 181,000 before the transaction and 0 after the transaction. This means the sender's account was fully emptied. This type of pattern may indicate fraud, especially when combined with other suspicious transaction behavior.

7. Where Do These Numbers Come From?

In real banking or payment systems, these values come from transaction records. Every transaction can store the sender's balance before and after the transfer, the receiver's balance before and after the transfer, and the amount transferred.

In this project, the numbers come from the CSV dataset used for training: PS_20174392719_1491204439457_log.csv. The same type of values are entered into the Streamlit application when testing a new transaction.

8. How the XGBoost Model Works in This Project

XGBoost is a machine learning algorithm that builds many decision trees. Each tree learns patterns from the transaction dataset. The final model combines the decisions of these trees to make a prediction.

During training, the model studies examples of both legitimate and fraudulent transactions. It learns which balance patterns are more common in fraud cases and which patterns are more common in normal transactions.

9. System Workflow

  1. The dataset is loaded from the CSV file.
  2. The five important features are selected.
  3. The data is split into training and testing sets.
  4. The XGBoost model is trained using the training data.
  5. The trained model is saved as fraud_model.pkl.
  6. The Streamlit app loads fraud_model.pkl.
  7. The user enters transaction values into the app.
  8. The model predicts whether the transaction is fraudulent or legitimate.

10. How to Run the Real Model

The real XGBoost model runs through the Streamlit application, not through the static GitHub Pages website. To run the model locally, use these commands: 

python3 train_xgboost.py
streamlit run app.py

After running the Streamlit command, open the local app link in the browser. The usual local link is: 

http://localhost:8501

11. Important Note About GitHub Pages

GitHub Pages can display the project website, explanation, screenshots, and links. However, GitHub Pages cannot directly run Python, XGBoost, TensorFlow, or Streamlit. The real trained model must run locally through Streamlit or be deployed online using a service such as Streamlit Community Cloud.

12. Summary

The AI Fraud Detection System uses transaction amount and balance changes to classify transactions. Old Balance Origin and New Balance Origin refer to the sender's balance before and after the transaction. Old Balance Destination and New Balance Destination refer to the receiver's balance before and after the transaction. These values help the XGBoost model identify suspicious financial behavior.
